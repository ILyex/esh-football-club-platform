# تفعيل إشعارات المباريات على الموقع الحي

## ما أُضيف إلى المشروع

- نافذة اختيارية للمشجع في صفحات الموقع العام لتفعيل أو إيقاف إشعارات بداية المباراة والأهداف والنهاية.
- إشعارات Web Push من خلال Service Worker؛ يستطيع النظام عرضها والموقع مغلق بعد منح الإذن. على iPhone/iPad يلزم إضافة الموقع إلى الشاشة الرئيسية وفتحه منها.
- Outbox داخل معاملة الهدف والنتيجة، وطابور Cloudflare لإرسال منفصل مع إعادة محاولة ورسائل فاشلة.
- تفضيل اللغة، الاشتراك لكل جهاز، تنظيف الاشتراكات المنتهية، وتقليل التكرار.
- لا يشترط تسجيل حساب. الاشتراك يتابع فئات النادي الأربع حاليًا.

## تهيئة البيئة قبل النشر

1. أنشئ مفاتيح VAPID واحفظها في Cloudflare Secret مع نسخة محلية مستثناة من Git:

   ```powershell
   node scripts/provision-vapid-keys.mjs
   ```

   السكربت يحفظ نسخة خاصة محلية في `.dev.vars` ويضبط القيم الثلاث في Cloudflare. استخدم `mailto:dev@esh.dz` كقيمة `VAPID_SUBJECT`. لا تحفظ المفتاح الخاص في Git ولا تعِد توليده بعد اشتراك الأجهزة.

2. أنشئ الطابورين في حساب Cloudflare نفسه:

   ```powershell
   npx wrangler queues create esh-goal-push
   npx wrangler queues create esh-goal-push-dead
   ```

3. طبّق ترحيل قاعدة بيانات PostgreSQL:

   ```powershell
   npm run db:migrate:deploy
   ```

   شغّله من بيئة موثوقة تحمل `DATABASE_URL` للإنتاج، بعد أخذ نسخة احتياطية متبعة في تشغيل النادي.

4. انشر Worker من إعداد `wrangler.jsonc`. راقب Queue وDead Letter Queue وسجلات Worker بعد تجربة إذن على جهاز Android/iPhone فعلي.

## ملاحظات تشغيلية

- بداية المباراة المجدولة تُلتقط بواسطة Cron الموجود كل دقيقة؛ لذلك قد يصل التنبيه المجدول متأخرًا حتى دورة Cron التالية. البدء اليدوي يرسل بعد حفظ الحالة مباشرة.
- يرسل النظام هدفًا جديدًا يُسجل في مباراة مباشرة. أهداف التقارير التاريخية والاستيراد لا تُحوّل إلى تنبيهات حية.
- لا أستطيع تأكيد وصول فعلي للهاتف قبل إضافة مفاتيح VAPID والطوابير وتطبيق الترحيل والنشر على Cloudflare. في غياب المفتاح، تعرض الواجهة أن الخدمة غير مهيأة وتبقى بقية المنصة مستقلة عنها.
- إن تجاوز استدعاء WebCrypto حد CPU الفعلي في خطة Cloudflare، تبقى رسالة Queue قابلة لإعادة المحاولة؛ يجب مراقبة CPU في أول تشغيل حقيقي.
