# تشغيل المنصة المحلية بنقرة واحدة

استخدم ملف `Launch-ESH-Platform.vbs` أو اختصار سطح المكتب من جهاز النادي. لا يحتاج الإداري إلى فتح
PowerShell أو كتابة `npm run dev`.

## أول تشغيل

يجهّز مسؤول التقنية الجهاز مرة واحدة فقط: يثبت Node.js ‏22.12 أو أحدث، يضع ملف
`.env.local`، ويشغّل `npm ci` ثم `npm run build:cpanel`. بعد اكتمال التجهيز لا
يشغّل الإداري أي طرفية أو أمر npm؛ الاختصار يتحقق من وجود الحزمة ويفتح المتصفح
مباشرة. إذا كانت الحزمة ناقصة تظهر رسالة واضحة بدل بدء تثبيت أو بناء طويل أمام
الإداري.

ضع `NEXT_PUBLIC_PUBLIC_SITE_URL` في `.env.local` على عنوان الموقع العام المنشور
(حالياً `https://esh.football-club-platform.workers.dev`).
بهذا يفتح زر «العودة إلى الموقع الرسمي» الموقع العام مباشرة حتى عندما تعمل
لوحة الإدارة على `http://localhost:3000`.

المشغّل يحدد تلقائياً `DEPLOY_TARGET=node` حتى لا تختلط ملفات معاينة Cloudflare
المحلية مع تشغيل Node.js وقاعدة Neon المحلية.

قد يستغرق أول تشغيل وقتاً أطول لأنه يثبت الاعتماديات ويبني نسخة الإنتاج المحلية.
بعد ذلك يفتح الملف صفحة تسجيل الدخول تلقائياً على:

`http://localhost:3000/ar/login`

## وضع التشغيل

- `PUBLIC_SITE_ONLY=false` — لوحة الإدارة المحلية متاحة.
- `AI_ENABLED=true` — Ollama المحلي مفعّل.
- `NEXT_PUBLIC_AI_ENABLED=true` — أزرار الذكاء المحلية ظاهرة.
- `OLLAMA_MODEL=qwen2.5:7b` — نموذج النص والتحليل.
- `OLLAMA_VISION_MODEL=llava:7b` — نموذج قراءة الصور وملفات PDF الممسوحة.
- `OLLAMA_KEEP_ALIVE=2m` — إبقاء النموذج جاهزاً لفترة قصيرة حتى لا يمتلئ جهاز 4GB بالذاكرة.
- الموقع العام يبقى على Cloudflare ويستخدم قاعدة Neon نفسها.
- صور الموقع ومقاطع الفيديو العامة تُحفظ في جدول وسائط بقاعدة Neon افتراضياً، ولا تتراكم في قرص جهاز النادي. عند تحديث الإصدار، يجب تطبيق migrations على Neon قبل إرسال الحزمة؛ أما الوثائق الإدارية الخاصة فتبقى في مسار التخزين الخاص.

## تجهيز الذكاء المحلي مرة واحدة

بعد تثبيت Ollama على جهاز النادي، نفّذ مرة واحدة:

```powershell
ollama pull qwen2.5:7b
ollama pull llava:7b
```

بعد ذلك يكفي الضغط على أيقونة المنصة. المشغّل يبدأ Ollama في الخلفية ويشغل
التحليل النصي وOCR للصور وملفات PDF الممسوحة عند الحاجة. إذا كان نموذج الرؤية
غير مثبت، تحفظ الوثيقة وتظهر كمراجعة غير مكتملة بدلاً من اعتماد نتيجة غير موثوقة.

إذا كانت المنصة تعمل مسبقاً، يعيد الملف استخدامها ولا يشغل نسخة ثانية.
يعمل مشرف مخفي وخفيف عبر Node المرفق بالمنصة على فحص صحة الخادم كل 30 ثانية،
ويعيد تشغيله إذا تعطلت عملية Node أو ظلت المنصة غير مستجيبة. كما يُضاف اختصار صامت إلى بدء تشغيل Windows
ليبدأ الخادم بعد تسجيل الدخول إلى حساب جهاز النادي؛ لا يفتح المتصفح تلقائياً.
يحتاج الجهاز إلى البقاء مشغّلاً وحساب الاستضافة إلى البقاء مسجلاً في Windows
حتى تظل المنصة متاحة على الشبكة. وعند فشل التشغيل، راجع `.local-admin.log` و
`.local-admin-supervisor.log` بجانب الملف.

## اختصار سطح المكتب

الاختصار المجهز يشغّل ملف VBS المخفي، لذلك لا تظهر نافذة CMD. غيّر اسمه إلى
`منصة النادي الرياضي`، واجعل الأيقونة `public/branding/esh-logo.ico`.

للتثبيت على جهاز جديد، شغّل `Install-ESH-Platform.vbs` مرة واحدة من الحزمة
المضغوطة. ينقل الملفات إلى مجلد المستخدم، وينشئ الاختصار تلقائيًا على سطح
المكتب. بعد ذلك يستخدم الإداري الاختصار فقط.

حزمة النادي المبسطة (`npm run package:club`) تعرض للمستخدم ملفي اختصار فقط:
`SETUP.lnk` لتثبيت المنصة و`AI SETUP.lnk` لتجهيز Ollama مرة واحدة. بقية الملفات
موجودة داخل مجلد مخفي ولا يحتاج الإداري إلى فتحه.

## إرسال تحديث إلى جهاز النادي

بعد تعديل الكود، طبّق migrations على قاعدة Neon المقصودة (`npm run db:migrate:deploy`)، ثم أنشئ حزمة إنتاج جديدة (`npm run build:cpanel`) وأرسل الحزمة
المضغوطة إلى مسؤول النادي عبر قناة خاصة. يفك مسؤول التقنية الحزمة ثم يشغّل
`Update-ESH-Platform.vbs` مرة واحدة. الأداة توقف نسخة المنصة فقط، تستبدل ملفات
التشغيل، تحفظ `.env` و`.env.local` وبيانات Ollama، ثم تعيد فتح المنصة. لا يحتاج
الإداري إلى Git أو PowerShell أو `npm`، ولا تُرفع ملفات الأسرار إلى GitHub.
