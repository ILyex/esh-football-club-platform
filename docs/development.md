# Development Setup

## Requirements

- Node.js 20.9 or newer
- npm
- PostgreSQL 14 or newer
- A local `.env` based on `.env.example`

The source folder is currently under OneDrive on Windows. OneDrive can scan,
index and synchronize the large number of files generated by Next.js. For
faster startup and hot reload, keep active development checkouts outside
OneDrive and other synchronized folders when practical.

## First run (PowerShell)

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm ci
npm run db:migrate:deploy
npm run dev
```

For background jobs such as hourly insight and notification updates, start
`npm run worker` in a second terminal. Page requests do not perform full-club
notification scans.

Set `DATABASE_URL` and a unique `AUTH_SECRET` in `.env` first. The `postinstall`
script generates Prisma Client. `db:migrate:deploy` applies the checked-in
migrations without creating a new migration. Use `npm run db:push` only for a
disposable local database when intentionally prototyping schema changes.

The app uses local filesystem storage in development when S3 storage is not
configured. Local private files go under `.storage/private`; public media goes
under `.storage/public`. These files are ignored by Git and should not be
committed.

## Development workflow

1. Create a migration for schema changes with `npm run db:migrate` against a
   development database.
2. Update server-side authorization and team scope along with every data
   mutation.
3. Add or update both locale message trees and run `npm run i18n:check`.
4. Run the relevant unit suite and `npm run typecheck` before submitting work.
5. Run `npm run build` for changes affecting routing, server components,
   configuration or production dependencies.

Never point a local seed or test script at production data. Integration tests
that use a live database are documented in `tests/finance/README.md`.

## Troubleshooting

- **Slow route compilation or hot reload:** use `npm run dev` (Turbopack) and
  move the checkout out of OneDrive. Stop duplicate Next.js development
  servers sharing the same checkout.
- **Prisma client does not match the schema:** run `npm run db:generate`.
- **Missing database tables:** check `DATABASE_URL`, then run
  `npm run db:migrate:deploy` against the intended local database.
- **Port 3000 is busy:** stop the other development server before starting a
  second one; do not share one `.next` directory between builds and dev
  servers.
- **Private downloads fail locally:** ensure local storage is enabled and the
  `AUTH_SECRET` is set. In production, configure a private S3-compatible
  bucket instead.

## GitHub and clean checkouts

Use `npm ci` for a reproducible install from `package-lock.json`. `.env`,
`.env.local`, local uploads, build output and `scratch/` are intentionally
excluded from Git. Copy `.env.example` to `.env` and enter local values there;
never add real credentials or club data to the example file.
