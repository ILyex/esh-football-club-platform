# خطة نقل المنصة إلى Cloudflare ضمن الميزانية

## الحالة الحالية

- أضيف مسار بناء Cloudflare Workers بواسطة OpenNext، مع إبقاء مسار Next.js/Node الحالي كما هو.
- ستبقى قاعدة البيانات PostgreSQL؛ لن ننقلها إلى D1، لتجنب إعادة كتابة الاستعلامات المالية والمهام والصلاحيات.
- أضيف اتصال Prisma خاص بـ Workers عبر موائم Neon serverless باستخدام WebSocket؛ لا يستخدم التطبيق Hyperdrive في مسار الطلبات.
- أُضيف تضمين مسبق لمحرك Prisma WebAssembly في حزمة Worker لتجنب التجميع الديناميكي الذي تمنعه بيئة Cloudflare.
- طُبقت إضافة جدول FAF الجديدة على قاعدة Neon الحالية؛ كل ترحيلات Prisma الآن مطبقة.
- يوجد مشروع Neon تجريبي منفصل وفارغ في Frankfurt؛ استُخدم أثناء البناء المحلي فقط، ولم يربط به Worker المنشور.
- تعذر تفعيل R2 لعدم توفر بطاقة دفع؛ استُبدل بمخزن Neon Object Storage ضمن الخطة المجانية.
- أُنشئت حاويتان خاصتان على فرع الإنتاج: `esh-private` للوثائق، و`esh-public` للوسائط. نُقلت 18 وثيقة وملفًا خاصًا وملفا وسائط عامان (نحو 7.9 MB)، مع إبقاء النسخ المحلية.
- اختُبرت الكتابة والقراءة وروابط التنزيل الموقعة عبر S3 في الحاويتين، وحُذف ملفا الاختبار بعد التحقق.
- نُشر Worker على `workers.dev` باستخدام سر `DATABASE_URL` للاتصال بقاعدة Neon الحالية. جرى فحص تتابعي حي للمسارات `/ar` و`/fr` وواجهتي تسجيل الدخول العربية والفرنسية، وكذلك نقاط NextAuth العامة؛ كلها أعادت HTTP 200.
- لم أجرّب تسجيل الدخول بحساب إداري أو وظائف لوحة الإدارة؛ يلزم فحصها يدويًا قبل مشاركة الرابط مع إدارة النادي.
- لم يُربط نطاق مخصص بعد. النشر لا يثبت أن جميع وظائف المنصة اجتازت اختبار تشغيل حي.

## البنية المقترحة

```text
المستخدمون
   │
Cloudflare Worker (Next.js عبر OpenNext)
   ├── Prisma + Neon serverless (WebSocket) ── Neon PostgreSQL
   ├── Neon Object Storage ── الملفات العامة والخاصة (S3)
   └── Cron كل 15 دقيقة ── /api/cron/process-jobs
```

المسار التجريبي يستهدف الخطط المجانية؛ راقب حصص Cloudflare وNeon شهريًا. Neon Free (حسب المعلن في أكتوبر 2026) يشمل حتى 100 مشروع، و1 GB لقاعدة البيانات، و100 CU-hour لكل مشروع شهريًا، وتوسّعًا تلقائيًا حتى 2 CU، و10 فروع، و5 GB لتخزين الكائنات؛ قاعدة البيانات تتوقف بعد الخمول وتستيقظ عند أول طلب. هذه الحصص قد تتغير:

- [Cloudflare Workers](https://developers.cloudflare.com/workers/platform/pricing/)
- [Neon Free plan update (October 2026)](https://neon.com/blog/neon-free-plan-1-gb-per-project)
- [Neon Object Storage](https://neon.com/blog/neon-backend-is-ga)

هذا المسار يناسب الإطلاق التجريبي والاستخدام المنخفض بعد قياس الحصص، لكنه لا يقدم ضمان توافر تعاقديًا ضمن الخطط المجانية. قد يتأخر أول استعلام بعد خمول Neon، وقد تتوقف طلبات Worker عند بلوغ الحصة اليومية. يجب قياس استهلاك CPU وعدد استعلامات DB للصفحات الديناميكية والمهام قبل وضع بيانات النادي المالية عليه. كما أن 100 CU-hour من Neon قد لا تكفي إذا ظل compute نشطًا معظم الشهر؛ راقب لوحة الاستخدام. لا يمكن ضمان تشغيل مالي إنتاجي بلا انقطاع ضمن صفر تكلفة.

## خطوات تجهيز الحسابات

1. سجّل Wrangler في حساب Cloudflare؛ اكتمل ذلك. لا ترسل كلمة المرور أو API token في المحادثة.
2. التطبيق يستخدم مشروع Neon `ESH-P5-Test` وقاعدة الإنتاج الحالية دون نسخ بياناتها؛ ترحيل قاعدة البيانات اللازم لجلسات FAF مطبق.
3. اتصال Worker بقاعدة البيانات محفوظ في سر Cloudflare `DATABASE_URL` فقط، وليس في المستودع أو `wrangler.jsonc`.
4. بسبب تعذر تفعيل R2، يستخدم التطبيق Neon Object Storage المتوافق مع S3. الحاويتان الخاصتان جاهزتان؛ الصور والوسائط العامة ستُخدم عبر مسار Worker دون كشف الحاوية مباشرة.
5. اكتمل نقل ملفات `.storage/private` و`.storage/public` مع الحفاظ على مفاتيحها؛ النسخ المحلية ما زالت موجودة.
6. أُضيفت أسرار Neon S3 و`AUTH_SECRET` و`CRON_SECRET` إلى Worker كأسرار Cloudflare؛ لم تُحفظ القيم في `wrangler.jsonc` أو GitHub، وحُذفت ملفات الأسرار المؤقتة المحلية.
7. نُشرت المنصة على: https://esh-football-platform.football-club-platform.workers.dev . العربية والفرنسية وصفحتا الدخول اجتازت فحص استجابة حي متتابع.
8. قبل اعتماد الرابط رسميًا، اختبر تسجيل دخولك الفعلي، والملفات، ووظائف الإدارة، والمهام المجدولة. لا تغيّر DNS قبل ذلك وشراء النطاق.

## الوظائف التي تحتاج تدقيقًا قبل النقل

- جلسة تكامل FAF تحفظ نسخة مشفرة في PostgreSQL عند تشغيل Worker (ويظل وضع الملف المحلي للاختبارات/Node). عند بدء Worker جديد يجب ربط FAF من جديد من لوحة الإدارة؛ الجلسة المحلية القديمة لا تنتقل تلقائيًا.
- خدمة AI الحالية تشير إلى Ollama على جهاز/خادم خارجي؛ هذا العنوان المحلي لن يكون متاحًا من Cloudflare. يلزم مزود قابل للوصول من الإنترنت أو تعطيل AI في الإنتاج.
- تخزين الملفات المحلي والتنزيلات المحلية لا يصلحان في Worker؛ تنزيلات المستندات الخاصة تستخدم روابط S3 موقعة بعد فحص الصلاحيات، والوسائط العامة تقدم عبر Worker. اختبر الرفع والتنزيل بحساب إداري قبل اعتماد الإنتاج.
- توجد قاعدة Neon staging منفصلة للاختبار، ولم تُنقل إليها بيانات الإنتاج. استخدمها في المعاينة ولا تضع أسرارها في Git.
- جرى تشغيل معاينة OpenNext على Windows بنجاح رغم تحذير OpenNext من أن WSL أفضل لاستقرار البناء؛ للبناء المتكرر والنشر الآلي يوصى باستخدام Linux/WSL.

## أوامر محلية بعد إعداد Neon

```powershell
npx wrangler login
npm run build:cloudflare
npx opennextjs-cloudflare preview
```

ضع `DATABASE_URL` التجريبية في `.dev.vars` قبل المعاينة، واستخدم قاعدة Neon التجريبية فقط. لا تستخدم `preview --remote` على قاعدة البيانات الحية قبل أخذ نسخة احتياطية ومراجعة كل عملية كتابة. أمر `npm run build:cloudflare` يتضمن تجهيز ملفات Prisma WebAssembly تلقائيًا.
