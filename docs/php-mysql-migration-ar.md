# خطة ترحيل المنصة إلى الاستضافة المشتركة الشائعة

## الهدف

جعل نسخة الإنتاج قابلة للتشغيل على الاستضافة المشتركة التي توفر PHP وMySQL أو
MariaDB وApache/LiteSpeed وCron وSSL، مع إبقاء نسخة Next.js الحالية تعمل أثناء
الترحيل. لن نبدل الخادم دفعة واحدة، لأن ذلك قد يترك النادي بلا لوحة إدارة أو
نسخة قابلة للطباعة.

## القرار المعماري

- الواجهة العامة ولوحة الإدارة الجديدة: PHP 8.2+ مع قوالب HTML وCSS/JavaScript
  خفيفة، من دون Node.js وقت التشغيل.
- الخادم: PHP PDO مع استعلامات محضرة، جلسات HttpOnly وSameSite=Lax، وطبقة صلاحيات
  مركزية.
- قاعدة البيانات: MySQL 8 أو MariaDB 10.6+، مع `utf8mb4` ووقت UTC.
- الملفات: مجلد خاص خارج `public_html`، وملفات عامة في مجلد الوسائط، مع حماية
  التنزيل عبر PHP بعد فحص الصلاحية.
- المهام: Cron يستدعي سكربت PHP بمفتاح داخلي؛ لا يوجد عامل Node دائم.
- الطباعة: صفحة HTML مستقلة تحمل CSS للطباعة بحجم A4؛ المتصفح يعرض نفس المصدر
  الذي يطبعه، من دون Server Action أو اعتماد على Chromium خاص.

## ما يلزم تغييره

المشروع الحالي يحتوي 49 نموذج بيانات و13 مسار API وحوالي 29 ملف Server Actions.
لذلك التحويل ليس تغيير `provider` في Prisma فقط. يجب نقل:

1. تسجيل الدخول والجلسات وإبطالها وتحديد المعدل.
2. RBAC والصلاحيات ونطاق الفريق والتدقيق الأمني.
3. اللاعبين والطاقم والفرق والمباريات والتدريب والوثائق والمالية.
4. رفع الملفات والتنزيلات الخاصة والقوالب والمستندات الرسمية.
5. المهام والإشعارات والتقارير والطباعة.

## مراحل التنفيذ

### المرحلة 0 — عقد التوافق (بدأت)

- تثبيت المتطلبات الدنيا: PHP 8.2، MySQL/MariaDB، Cron، SSL، ورفع ملفات قابل
  للضبط.
- حصر الجداول ومسارات API والصلاحيات.
- منع أي تعديل على نسخة Next.js الحالية أثناء بناء البديل.

### المرحلة 1 — النواة

- إنشاء مخطط MySQL مكافئ مع مفاتيح وفهارس وترميزات صحيحة.
- بناء محمل الإعدادات وPDO والهجرة والنسخ الاحتياطي.
- بناء الجلسة وتسجيل الدخول وRBAC وسجل التدقيق.
- إضافة اختبارات طلبات غير موثقة ومستخدمين بصلاحيات مختلفة.

### المرحلة 2 — بيانات النادي

- نقل اللاعبين والطاقم والفرق والمباريات والتدريب والبحث.
- استيراد PostgreSQL إلى MySQL مع تقرير تحقق للعدد والمعرّفات والعلاقات.

### المرحلة 3 — الوثائق والطباعة

- نقل التخزين والتنزيلات والقوالب.
- إعادة بناء ورقة A4 كمصدر HTML واحد للمعاينة والطباعة.
- اختبار Chrome وEdge وFirefox على نفس الملف الناتج.

### المرحلة 4 — المالية والتكاملات

- نقل المالية والتقارير والإشعارات والمهام.
- جعل Gmail وFAF والذكاء المحلي إضافات اختيارية لا تمنع تشغيل المنصة الأساسية.

### المرحلة 5 — القطع التدريجي

- تشغيل النسخة PHP على نطاق فرعي وبيانات staging.
- مقارنة الصلاحيات والبيانات والطباعة.
- تحويل DNS فقط بعد نجاح الاختبارات والنسخ الاحتياطي والاستعادة.

## ما لن ننقله إلى الاستضافة المشتركة

لن تعتمد النسخة المشتركة على Node.js أو Prisma أو PostgreSQL أو OpenNext أو Ollama
وقت التشغيل. الذكاء المحلي، تحويل PDF الخارجي، Gmail وFAF تبقى ميزات اختيارية؛
غيابها لا يمنع إدارة النادي الأساسية.

## معيار القبول

لا تعتبر النسخة الجديدة جاهزة حتى تنجح المصادقة، الصلاحيات، رفع وتنزيل وثيقة
خاصة، البحث، إضافة لاعب، إنشاء وثيقة A4، الطباعة من Chrome وEdge، Cron، النسخ
الاحتياطي والاستعادة، واختبار الوصول المباشر بلا جلسة.
