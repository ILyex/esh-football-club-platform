# دراسة معمارية: بث مباريات الجمعية عبر YouTube

تاريخ الدراسة: 28 أكتوبر 2026

## القرار المقترح

نبدأ ببث المباراة من YouTube Studio أو من تطبيق بث معتمد، ثم يحفظ الإداري رابط البث في سجل المباراة من منصة الإدارة. يعرض تطبيق الجمهور صفحة مباراة فيها مشغل YouTube الرسمي عند تفعيل البث. لا ننقل الفيديو عبر خوادم المنصة.

هذا المسار أقل كلفة وتعقيدًا، ويستفيد من توزيع YouTube للفيديو وجودته المتكيفة. يقتصر استهلاك موارد تطبيق الجمهور على فتح المشغل عند اختيار المستخدم للمباراة.

## تجربة الجمهور والإدارة

1. يجهّز مسؤول البث البث في قناة الجمعية على YouTube، ويختبر الكاميرا والصوت والاتصال.
2. يربط الإداري رابط الفيديو بالمباراة ويختار حالة «مبرمج»، ثم «مباشر» عند بدء البث، و«منتهٍ» عند إيقافه.
3. تعيد واجهة API العامة بيانات البث للمباراة المنشورة فقط.
4. تظهر بطاقة «مباشر» في المباراة. يضغط المشجع على «مشاهدة البث» لفتح صفحة المشاهدة.
5. يبدأ تشغيل الفيديو بعد ضغط المستخدم على زر YouTube، مع زر احتياطي لفتح البث في تطبيق YouTube أو المتصفح.

## بنية المرحلة الأولى

- **مصدر البث:** YouTube Studio أو تطبيق/مشفّر RTMP موثوق. تظل إدارة البث ومفاتيح الإدخال في YouTube، ولا تظهر المفاتيح في تطبيق الإدارة.
- **منصة الإدارة:** حقل رابط YouTube للمباراة، حالة البث، صلاحية تعديل، ومعاينة للرابط قبل الحفظ. يمنع تخزين رابط RTMP أو stream key في بيانات المباراة.
- **قاعدة البيانات:** حقل اختياري لمعرّف فيديو YouTube وحالة البث، أو استخراج المعرّف والتحقق منه عند حفظ الرابط. لا حاجة لتخزين رابط مشاهدة حر غير موثوق.
- **واجهة الجمهور:** API يعيد معرّف الفيديو وحالته فقط للمباريات المرئية للجمهور. صفحة مشاهدة مخصصة، زر رجوع وتفاصيل المباراة، ومعالجة لحالات ما قبل البث وانتهائه وعدم توفر الفيديو.
- **المشغل:** YouTube IFrame Player داخل WebView مضبوط في التطبيق الأصلي، أو صفحة مشاهدة ويب داخل التطبيق. يُحمّل عند فتح صفحة البث فقط، ويبدأ بإجراء من المستخدم، ويحافظ على شعار YouTube وأدواته والإعلانات والروابط القياسية.
- **الإشعارات:** إرسال إشعار بدء البث لمتابعي المباراة اختياريًا، مع رابط عميق إلى صفحة المشاهدة. لا نرسل إشعارات دورية عن زمن البث.

## لماذا لا نمرّر الفيديو عبر خوادمنا؟

تمرير الفيديو عبر خادم النادي يضيف فاتورة نقل وتخزين، ونقطة فشل إضافية، ومتطلبات ترميز وتكييف جودة ومراقبة. مع YouTube، جهاز التصوير يرفع البث إلى YouTube، ومشاهد التطبيق يستقبل الفيديو من مشغل YouTube مباشرة. التطبيق يحتفظ فقط ببيانات المباراة ورابط الفيديو وحالته.

## التكامل الآلي لاحقًا

إذا أردنا أزرار «ابدأ البث» و«أوقف البث» داخل تطبيق الإدارة، فواجهة YouTube Live Streaming API تستطيع إنشاء حدث بث وجدولته وربط `liveBroadcast` بـ `liveStream` ثم نقل حالته بين الاختبار والبث والنهاية. هذه الواجهة **تدير حدث YouTube ولا ترمّز فيديو كاميرا الهاتف ولا ترفعه بدل التطبيق**.

يتطلب هذا المسار مشروع Google Cloud وواجهة YouTube Data API وOAuth لقناة الجمعية. تحفظ رموز OAuth طويلة العمر على خادم موثوق، لا في APK أو المتصفح. ويظل إرسال الفيديو بحاجة إلى مشفّر/مرسل RTMP داخل جهاز البث أو برنامج بث خارجي؛ ويجب اختبار حرارة الهاتف والبطارية والشبكة وجودة الرفع قبل اعتماده.

لذلك نؤجل التكامل الآلي إلى ما بعد نجاح المرحلة الأولى، ثم نقيّم مكتبة ترميز Android مرخصة أو نُبقي تطبيق بث خارجيًا. لا نبني RTMP relay خاصًا ما دام YouTube يستقبل الإرسال مباشرة.

## حدود وسياسات يجب مراعاتها

- ظهور البث على قناة YouTube يخضع لأهلية القناة وإعداداتها. للبث من تطبيق YouTube على الهاتف شروط خاصة، منها توثيق القناة، عدم وجود قيود بث حديثة، وحد أدنى للمشتركين؛ تتحقق الإدارة من أهلية القناة قبل يوم المباراة.
- يجب احترام حقوق تصوير ونقل المنافسة. وجود رابط أو قناة لا يمنح حق بث مباراة رسمية تلقائيًا.
- استخدام مشغل YouTube يتطلب إبقاء تجربة المشغل وبياناته وإعلاناته ووسائل التحكم القياسية كما يحددها YouTube. لا نخفي الشعار ولا نضع عناصر تغطي أزرار المشغل، ولا نبدأ التشغيل تلقائيًا.
- لا تعرض صفحة الجمهور رابط بث خاص أو غير منشور للعامة. حالة البث وحدها لا تكفي لإثبات أن الفيديو متاح للمشاهدة.
- لا يوجد بث «مجاني بلا تكلفة» على الهاتف: لا نحتاج خادم بث مدفوع في هذا التصميم، لكن رفع الفيديو يستهلك بيانات وبطارية جهاز المرسل، وقد يطبق YouTube إعلاناته وسياساته على الفيديو.

## التوسع والاعتمادية

- إبقاء البث منفصلًا عن واجهة الرئيسية؛ لا ينزل الفيديو ولا يبدأ المشغل قبل دخول صفحة المشاهدة.
- استخدام YouTube adaptive streaming، وعدم polling من التطبيق لمعرفة حالة البث. يغير الإداري الحالة، أو تستخدم خدمة مجدولة/YouTube API لاحقًا للتحقق عند الحاجة.
- تخزين معرّف YouTube وحالة واضحة: `SCHEDULED`, `LIVE`, `ENDED`, `UNAVAILABLE`.
- عند فشل التضمين، عرض تفسير مختصر ورابط فتح YouTube. وعند نهاية المباراة، إبقاء إعادة المشاهدة إذا كانت متاحة.
- إطلاق أولي لمباراة تجريبية غير رسمية، قياس زمن البدء والأعطال على Wi-Fi و4G/5G، ثم تشغيل البث الرسمي بعد مراجعة الحقوق.

## أسئلة تنفيذية قبل المرحلة الأولى

- هل قناة الجمعية موثقة ومفعّل فيها البث المباشر؟
- من يملك صلاحية ربط الفيديو بالمباراة وإعلان بدء/نهاية البث؟
- هل توجد موافقة مكتوبة على بث مباريات المنافسات الرسمية؟
- من جهاز التصوير، وما سرعة رفعه ومصدر طاقته ومكان تثبيته؟
