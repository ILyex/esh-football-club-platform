# ESH Branding Assets

All derived from the one real official logo (`esh-logo.jpg`, as supplied) —
none of these are redesigned, distorted, or invented. Every variant below was
generated by flood-filling the JPG's connected corner background to
transparent, then re-coloring or resizing that transparent master. The
badge's proportions, ring, monogram, and lettering are pixel-identical to
the source in every variant.

## Files

| File | What it is | Use it for |
|---|---|---|
| `esh-logo.jpg` | Original supplied file, white square background | Anywhere a plain rectangular image is fine and the surface behind it is white/light (e.g. embedded in a generated Word document that expects a rectangular image slot) |
| `esh-logo-transparent.png` | Full-resolution (960×959), transparent outside the circular badge | Master asset for light backgrounds — public site header/hero, footer, print |
| `esh-logo-dark-bg.png` | Transparent, brand red ring preserved, black outline/monogram/text inverted to white | Dark backgrounds / dark mode — the red ring already reads fine on dark surfaces; only the near-black linework would otherwise disappear, so only that gets inverted |
| `esh-logo-256.png` / `-128.png` / `-64.png` / `-32.png` | Transparent, resized (LANCZOS) | Compact contexts: `-64`/`-32` for the dashboard sidebar and favicon-sized uses, `-128` for the login/auth screen, `-256` for a public-site header logo |

## Usage rules (part of the design system, not ad-hoc per page)

- Never place `esh-logo.jpg` (white background) over anything but a white/near-white surface — its square white corners will visibly clash otherwise. Use `esh-logo-transparent.png` (or a sized variant) everywhere else.
- Dark surfaces (dark mode, dark hero sections, dark document headers) use `esh-logo-dark-bg.png`, never the plain transparent color version — the black linework needs the inversion to stay legible.
- Never re-stretch a variant to a non-square aspect ratio — the badge is circular and any distortion is immediately visible.
- Prefer the closest pre-generated size over scaling a larger file down in CSS/HTML — the compact sizes were resampled properly (LANCZOS), not just shrunk with `width`/`height` attributes.

## Currently wired in code

- Login screen: `esh-logo-128.png`
- Dashboard sidebar header: `esh-logo-64.png`
- `ClubSettings.logoUrl` (Settings page, upload/replace flow): defaults to `esh-logo.jpg`; re-uploading via Dashboard → Settings switches to the public S3 bucket per `lib/storage.ts`

## Not yet wired (public site doesn't exist yet beyond the foundation homepage)

Public header, hero, footer, and dark-mode logo swapping are not implemented
yet because the public website and dark mode themselves aren't built yet.
When they are, follow the table above rather than reaching for
`esh-logo.jpg` by default.

## Regenerating variants

If a new official logo file is ever supplied, regenerate everything with
the same flood-fill approach (corner-seeded, not a global white threshold —
a global threshold would also erase the white lettering and inner medallion
that are supposed to stay opaque) rather than manually redrawing anything.
